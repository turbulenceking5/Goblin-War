# Secondary Pages

Four pages reachable from index.html's toolbar nav icons, alongside settings.html (its own file, see [characters.md](characters.md)). All four share the same page chrome: a sticky header with a title and a "&larr; Back to Map" button (cache-busted — `location.href='index.html?_='+Date.now()`, see the cache-busting convention in [../CLAUDE.md](../CLAUDE.md)), and a parchment-colored `<main>` capped at `max-width:520px`. character.html, skills.html, and inventory.html each also have their own `#toast`/`showToast()` (same markup/CSS as index.html's, duplicated per the no-modules convention) now that all three can mutate state (equip/unequip, spend a skill point) and need to confirm it happened.

## character.html — Hero Sheet

Mostly display, with one real interaction now — reads every stat key listed in [player-state.md](player-state.md) once on load and writes the values into the DOM (`hero-name` off `goblinwar_characterName`, `hp-bar`/`hp-value`, `stamina-bar`/`stamina-value`, `age-value`, `gold-value`, `current-date`, `food-value`, `weight-value`), and re-renders live (`renderEquipment()`) when you unequip something. Nothing else updates without a reload — if you fight, take damage, or equip something *from inventory.html* while this tab is open elsewhere, it won't reflect that until you come back to it. Food carried and carried weight are computed here the same way index.html does (parse `goblinwar_inventory`, find the `"Food"` stack, sum `weight*qty` across everything), and carried weight is checked against `getCarryCapacity()` (duplicated from index.html — only the Pack Mule perk affects it, see [player-state.md](player-state.md)) rather than a flat constant.

Deliberately **identity and status only** now — Level, Strength/Agility/Intelligence, Perks, and Special Attacks all moved to [skills.html](../skills.html) below, at the project owner's request, so the two screens don't compete for the same space:
- **Hero name + tag** (`.hero-name`, `.hero-tag`): off `goblinwar_characterName`; the race tag is still hardcoded "Human" — see "Character creation & race" in [roadmap.md](roadmap.md).
- **Portrait box** (`.portrait-box`): a dashed placeholder frame around a simple hero-silhouette SVG, labeled "Character portrait — coming soon" — the character-sheet equivalent of the location-view art box (see [locations-and-camp.md](locations-and-camp.md)), reserving the spot rather than pretending there's real per-character art.
- **Equipment** (`.slot-grid.equip`, 3×2, `renderEquipment()`): reads `goblinwar_equipped` and shows each filled slot's item name (`.equip-slot.filled`), with a `.combat-bonus` line summing every equipped item's `dmg`/`def` (see [player-state.md](player-state.md)). Tapping a filled slot unequips it (`setEquippedSlot(slot, null)`) and re-renders in place; there's no way to equip *from* this page, only unequip — equipping happens on inventory.html.
- **Accessories** (`.slot-grid.accessory`, 4×2): still fully cosmetic — unlabeled empty slots, not backed by anything, no accessory-type items exist yet (see [roadmap.md](roadmap.md)).

Text lives directly inside each Equipment slot rather than a `title` tooltip, since tooltips don't fire on touch. Gold is shown once, in its own Purse card lower down (`#gold-value`).

Two fixed display fields with no backing state at all: **Origin** is hardcoded to "Kingdom of Bary" (not derived from anything — there's currently no character-origin selection), and **Current location** is resolved by fetching `assets/travel-graph.json` just to look up `burgId`'s name (the page doesn't need the rest of the graph, just this one lookup).

## skills.html — Skills & Progression

Split out of character.html into its own toolbar tab. Everything here is real, not a placeholder — see [player-state.md](player-state.md)'s "Leveling & stats" for the mechanics and [combat.md](combat.md) for where the special attacks actually fire:

- **Level badge + XP bar** (`.level-badge`, `.xp-track`/`.xp-fill`): real numbers off `goblinwar_level`/`goblinwar_xp`, using the same `xpForLevel(level)` curve as index.html (duplicated per the no-modules convention).
- **Character Stats** (`.stats-box`): Strength/Agility/Intelligence, each with a "+" button that spends a skill point (`goblinwar_skillPoints`) to raise it by 1 — disabled once points run out.
- **Perks** and **Special Attacks** (`.perks-list`, two separate cards, both rendered through the shared `renderSkillList(list, containerId)`): the 9 passive perks and 6 active special attacks, each gated on a stat threshold and costing 1 skill point to unlock, sharing `goblinwar_skills` storage with no id collisions between the two lists. Unlocking either re-renders via `renderProgression()`, same as spending a stat point does — the actual mechanical effects (`getEquipDamageBonus`, `getCarryCapacity`, `combatAttack`, `combatSpecial`, `getBuyPrice`, etc.) all live in index.html; this page only drives the unlock UI, exactly as it did when it was part of character.html.

This page duplicates `PERKS`/`MOVES`/`xpForLevel`/`renderSkillList`/`renderProgression` from character.html's old copy (now index.html's canonical copy) rather than sharing a module, per the no-modules convention — see [../CLAUDE.md](../CLAUDE.md).

## inventory.html — Bag

Reads `goblinwar_gold` and parses `goblinwar_inventory` (defaults to `[]` on any parse failure, not a hardcoded fallback list — an empty bag renders "Your bag is empty." rather than the default starting items). A `.weight-card` above the item list shows carried weight vs. `CARRY_CAPACITY` (`40`, duplicated from index.html), turning red (`.over`) if somehow exceeded — shouldn't normally happen, since `addItem` in index.html refuses purchases that would push over the limit, but this page doesn't assume that invariant holds. The whole list is rendered by one `render()` function (called once on load, and again after every equip/unequip) rather than a one-shot template, so the page stays in sync with itself without a reload.

Each item renders as a row with a generic bag-icon SVG (not per-item icons), item name, a weight sub-line (`N wt each · M total`, only shown if the item has a `weight` field — older saves might not), a value badge (`Ng each`, only shown if the item has a `value` field — see [player-state.md](player-state.md)), and `×qty`. Items with a slot in the local `ITEM_STATS` table (mirrors `MARKET_ITEMS`' equippable entries, see [player-state.md](player-state.md)) additionally get a stat-bonus line and a full-width **Equip**/**Unequip** button (`.equip-btn`) — clicking it toggles `goblinwar_equipped[slot]` and calls `render()` again, so the row's own styling (`.item-row.equipped`, gold border) and button label flip immediately. Healing Potion, Books, and Firewood still get no button — there's no use/drop action for them yet.

**Waterskin and Bedroll are the first non-equippable items with a real effect**, per the project owner — see [roadmap.md](roadmap.md) for the full mechanics. Waterskin gets its own `.equip-btn`-styled **Drink** button (`id="drink-waterskin-btn"`, wired outside the generic `[data-equip-name]` loop since it has no `ITEM_STATS` entry) — the first "use a consumable" interaction in the game, disabled once already at full Stamina. This page duplicates its own `playerStamina`/`playerMaxStamina`/`setStamina`/`getItem`/`consumeItem` for this (it had never touched Stamina before), reading and writing the same `goblinwar_stamina` key index.html owns, so a drink taken here is immediately reflected back on the map. A `.stamina-card` above the item list (styled like the existing `.weight-card`) shows current/max Stamina so the player can see whether it's worth drinking before opening the row. Bedroll gets no button at all — its effect (see `BEDROLL_AMBUSH_MULT` in index.html) is passive, just from being carried — so its row instead shows a static italic `.item-note` line explaining what it does, the same slot a stat-bonus line would occupy for an equippable item.

Below the item list is a real Equipment section (`#equip-grid`, `.slot-grid.equip`) built the same way as character.html's — 6 slots, showing whatever's equipped, with a `#combat-bonus` line summing the totals. Tapping a filled slot here also unequips it, same as on character.html. This is the *only* page where you can equip something in the first place; character.html can only unequip.

## party.html — Companions

The simplest page in the game: header, one static "coming soon" block, no script tag at all. Placeholder for a future recruitable-companion system.

## Adding a new secondary page

Follow the existing pattern rather than inventing a new one: copy the shared CSS block (`:root` custom properties, `header`/`#back-btn`/`main`/`.subtitle` rules are near-identical across all four files), add the nav icon + `onclick="goTo('yourpage.html')"` to index.html's `#nav-icons` (see the cache-busting convention in [../CLAUDE.md](../CLAUDE.md) for why it's `goTo()` and not a bare `location.href`), and read `localStorage` directly rather than trying to pass state through the URL or a shared script — see root [CLAUDE.md](../CLAUDE.md) on why there's no shared module. Don't forget the two gate scripts in `<head>`/near the bottom of `<body>` (see [accounts.md](accounts.md)) — every player page needs them.
