# Secondary Pages

Five pages reachable from index.html's toolbar nav icons, alongside settings.html (its own file, see [characters.md](characters.md)). All five share the same page chrome: a sticky header with a title and a "&larr; Back to Map" button (cache-busted — `location.href='index.html?_='+Date.now()`, see the cache-busting convention in [../CLAUDE.md](../CLAUDE.md)), and a parchment-colored `<main>` capped at `max-width:520px`. character.html, skills.html, inventory.html, quests.html, and party.html each also have their own `#toast`/`showToast()` (same markup/CSS as index.html's, duplicated per the no-modules convention) now that all five can mutate state (equip/unequip, spend a skill point, abandon a quest, dismiss a mercenary) and need to confirm it happened.

## character.html — Hero Sheet

Mostly display, with one real interaction now — reads every stat key listed in [player-state.md](player-state.md) once on load and writes the values into the DOM (`hero-name` off `goblinwar_characterName`, `hp-bar`/`hp-value`, `stamina-bar`/`stamina-value`, `age-value`, `gold-value`, `current-date`, `food-value`, `weight-value`), and re-renders live (`renderEquipment()`) when you unequip something. Nothing else updates without a reload — if you fight, take damage, or equip something *from inventory.html* while this tab is open elsewhere, it won't reflect that until you come back to it. Food carried and carried weight are computed here the same way index.html does (parse `goblinwar_inventory`, find the `"Food"` stack, sum `weight*qty` across everything), and carried weight is checked against `getCarryCapacity()` (duplicated from index.html — only the Pack Mule perk affects it, see [player-state.md](player-state.md)) rather than a flat constant.

Deliberately **identity and status only** now — Level, Strength/Agility/Intelligence, Perks, and Special Attacks all moved to [skills.html](../skills.html) below, at the project owner's request, so the two screens don't compete for the same space:
- **Hero name + tag** (`.hero-name`, `.hero-tag`): off `goblinwar_characterName`; the race tag is still hardcoded "Human" — see "Character creation & race" in [roadmap.md](roadmap.md).
- **Title** (`.hero-title`, `#hero-title`, `hidden` by default): a small cosmetic line under the name/tag, shown once `goblinwar_kills` clears one of `TITLES`' thresholds — see [player-state.md](player-state.md)'s "Titles" section. No stat effect, purely a milestone flourish.
- **Portrait box** (`.portrait-box`): a dashed placeholder frame around a simple hero-silhouette SVG, labeled "Character portrait — coming soon" — the character-sheet equivalent of the location-view art box (see [locations-and-camp.md](locations-and-camp.md)), reserving the spot rather than pretending there's real per-character art.
- **Equipment** (`.slot-grid.equip`, 3×2, `renderEquipment()`): reads `goblinwar_equipped` and shows each filled slot's item name (`.equip-slot.filled`), with a `.combat-bonus` line summing every equipped item's `dmg`/`def` (all 14 slots, Equipment and Accessories alike) plus the Power Strike/Iron Skin perk bonuses if unlocked (see [player-state.md](player-state.md)) — matching index.html's real `getEquipDamageBonus()`/`getEquipDefenseBonus()` exactly, rather than under-reporting once either perk is unlocked. Tapping a filled slot unequips it (`setEquippedSlot(slot, null)`) and re-renders in place; there's no way to equip *from* this page, only unequip — equipping happens on inventory.html.
- **Accessories** (`.slot-grid.accessory`, 4×2) — done: 8 real slots (`ring_left`, `ring_right`, `amulet`, `cloak`, `belt`, `bracers`, `earring`, `charm`), backed by 8 new equippable `MARKET_ITEMS` entries (see [player-state.md](player-state.md)). Rendered by the same `renderSlotGrid(gridId, slots)` helper as the Equipment grid above, just called a second time against `ACCESSORY_SLOTS` into `#accessory-grid` — `renderEquipment()` now calls it twice rather than inlining one grid's markup.

Text lives directly inside each Equipment slot rather than a `title` tooltip, since tooltips don't fire on touch. Gold is shown once, in its own Purse card lower down (`#gold-value`).

Two fixed display fields with no backing state at all: **Origin** is hardcoded to "Kingdom of Bary" (not derived from anything — there's currently no character-origin selection), and **Current location** is resolved by fetching `assets/travel-graph.json` just to look up `burgId`'s name (the page doesn't need the rest of the graph, just this one lookup).

## skills.html — Skills & Progression

Split out of character.html into its own toolbar tab. Everything here is real, not a placeholder — see [player-state.md](player-state.md)'s "Leveling & stats" for the mechanics and [combat.md](combat.md) for where the special attacks actually fire:

- **Level badge + XP bar** (`.level-badge`, `.xp-track`/`.xp-fill`): real numbers off `goblinwar_level`/`goblinwar_xp`, using the same `xpForLevel(level)` curve as index.html (duplicated per the no-modules convention).
- **Character Stats** (`.stats-box`): Strength/Agility/Intelligence, each with a "+" button that spends a skill point (`goblinwar_skillPoints`) to raise it by 1 — disabled once points run out.
- **Perks** and **Special Attacks** (`.perks-list`, two separate cards, both rendered through the shared `renderSkillList(list, containerId)`): the 9 passive perks and 6 active special attacks, each gated on a stat threshold and costing 1 skill point to unlock, sharing `goblinwar_skills` storage with no id collisions between the two lists. Unlocking either re-renders via `renderProgression()`, same as spending a stat point does — the actual mechanical effects (`getEquipDamageBonus`, `getCarryCapacity`, `combatAttack`, `combatSpecial`, `getBuyPrice`, etc.) all live in index.html; this page only drives the unlock UI, exactly as it did when it was part of character.html.

This page duplicates `PERKS`/`MOVES`/`xpForLevel`/`renderSkillList`/`renderProgression` from character.html's old copy (now index.html's canonical copy) rather than sharing a module, per the no-modules convention — see [../CLAUDE.md](../CLAUDE.md).

## inventory.html — Bag

Reads `goblinwar_gold` and parses `goblinwar_inventory` (defaults to `[]` on any parse failure, not a hardcoded fallback list — an empty bag renders "Your bag is empty." rather than the default starting items). A `.weight-card` above the item list shows carried weight vs. `CARRY_CAPACITY` (`40`, duplicated from index.html), turning red (`.over`) if somehow exceeded — shouldn't normally happen, since `addItem` in index.html refuses purchases that would push over the limit, but this page doesn't assume that invariant holds. The whole list is rendered by one `render()` function (called once on load, and again after every equip/unequip) rather than a one-shot template, so the page stays in sync with itself without a reload.

Each item renders as a row with a generic bag-icon SVG (not per-item icons), item name, a weight sub-line (`N wt each · M total`, only shown if the item has a `weight` field — older saves might not), a value badge (`Ng each`, only shown if the item has a `value` field — see [player-state.md](player-state.md)), and `×qty`. Items with a slot in the local `ITEM_STATS` table (mirrors `MARKET_ITEMS`' equippable entries, see [player-state.md](player-state.md)) additionally get a stat-bonus line and a full-width **Equip**/**Unequip** button (`.equip-btn`) — clicking it toggles `goblinwar_equipped[slot]` and calls `render()` again, so the row's own styling (`.item-row.equipped`, gold border) and button label flip immediately.

Every row also gets a **Drop** button (`.drop-btn`, smaller and red-bordered rather than the full-width gold `.equip-btn` style, so it doesn't read as the row's primary action) that removes 1 of that item via `consumeItem` — the answer to [roadmap.md](roadmap.md)'s "Dropping (destroying an item for no gold) still doesn't exist" gap. Dropping the last copy of something currently equipped auto-unequips it first (same pattern as `sellItem` in index.html's Marketplace), with a note appended to the toast when that happens.

**Food and Waterskin are the game's two real consumables**, per the project owner — see [player-state.md](player-state.md)'s Hunger & Thirst section for the full mechanic. Food's row grows an **Eat** button (`id="eat-food-btn"`) and Waterskin's grows a **Drink** button (`id="drink-waterskin-btn"`) — both `.equip-btn`-styled and wired outside the generic `[data-equip-name]` loop since neither has an `ITEM_STATS` entry — the first "use a consumable" interaction in the game, each disabled once its meter is already at 0. This page duplicates its own `playerHunger`/`playerThirst`/`setHunger`/`setThirst`/`getItem`/`consumeItem` for this (it never touched either meter before), reading and writing the same `goblinwar_hunger`/`goblinwar_thirst` keys index.html owns so a meal taken here is immediately reflected back on the map. Two `.meter-card`s above the item list (styled like the existing `.weight-card`) show current/max Hunger and Thirst so the player can see whether it's worth eating/drinking before opening a row. Bedroll gets no button at all — both its effects (see `BEDROLL_AMBUSH_MULT`/`BEDROLL_STAMINA_BONUS` in index.html) are passive, just from being carried — so its row instead shows a static italic `.item-note` line explaining what it does, the same slot a stat-bonus line would occupy for an equippable item.

Below the item list is a real Equipment section (`#equip-grid`, `.slot-grid`, labeled "Equipment & Accessories") built the same way as character.html's — 14 slots (the original 6 plus the 8 Accessories slots, see [player-state.md](player-state.md)), all in one grid since this page never split them visually the way character.html does, showing whatever's equipped, with a `#combat-bonus` line summing the totals (gear plus the Power Strike/Iron Skin perk bonuses, same as character.html — see above). Tapping a filled slot here also unequips it, same as on character.html. This is the *only* page where you can equip something in the first place; character.html can only unequip.

## quests.html — Quests

A dedicated tab for the quest system described in [quests.md](quests.md), split off from the Quest Board panel's "Your Active Quests" list rather than replacing it — that list still shows up inside `showQuestBoardPanel` in index.html too, this page is just the one place to see everything outstanding *and* act on it without having to be standing at any particular settlement. Two sections, both driven by local (duplicated, per the no-modules convention) copies of `getQuests`/`getActiveQuests`/`getCompletedQuests`/`questTitle`/`questDesc`:

- **Active Quests** — every entry from `getActiveQuests()`, each card showing a **View Location** button (delivery quests only — see [quests.md](quests.md)) that hands off to index.html's `viewLocation()` via a `?viewBurg=` query param, alongside an **Abandon** button (`confirm()`-gated, same pattern character.html/characters.html's Delete Character use) that removes it from `goblinwar_quests` outright. Abandoning a Notable Figure kill-quest needs no special handling to free up its "one active at a time" cap (see [quests.md](quests.md)) — that cap is enforced by checking live storage every time that panel opens, so the slot is already free the instant the quest object is gone.
- **Recently Completed** — a read-only history list off a new `goblinwar_completedQuests` key (JSON array, newest first, capped at `COMPLETED_QUESTS_MAX` (20) entries), part of every character's save alongside `quests` (see [characters.md](characters.md)). Quests were previously just deleted on completion with nothing kept — `recordCompletedQuest(q)` in index.html now pushes a small `{type, giverName, targetName, reward, completedDay}` record at both completion sites (`checkQuestTurnIns` for deliveries, `endCombat`'s kill-quest payout branch) right before the quest itself is removed.

Delivery quest cards (both Active and Recently Completed) show how far the target is via `questDesc`'s `questDistanceNote` — `(`, `formatDuration(q.distanceHours)`, ` away)` appended to the description — using `distanceMiles`/`distanceHours` recorded on the quest object at accept time (see [quests.md](quests.md)'s "The Quest Board" section for where those come from), not recomputed here; this page never loads `travel-graph.json` at all.

## party.html — Companions & Mercenaries

No longer script-free — the roster/portrait system is real, and one half of it now has a real way in. A `COMPANIONS` catalog array (following the `ENEMY_VARIANTS`/`NOTABLE_FIGURES` pattern in index.html: one object per companion, no other code changes needed to add one) is the source of truth for every recruitable companion's `{id, name, title, portrait, blurb}` — it currently has three entries (Ser Brannoc Ward, Wren Sable, Thrain Emberforge), each with real generated art under `assets/party/`; `goblinwar_party` (JSON array of recruited companion ids, default `[]`) is which ones the player actually has. Still nothing can add an id to it — that's the still-unbuilt "recruit a companion" action described in [roadmap.md](roadmap.md)'s "Party / Companions" section, reserved for a future recruit-with-loyalty flow per the project owner, distinct from the mercenary flow below.

A companion's `portrait` points at a transparent-background PNG under `assets/party/`, downscaled to a 600px longest edge — the same convention `assets/enemies/` already follows (see [combat.md](combat.md)).

**Hired mercenaries are real.** `goblinwar_mercenaries` (JSON array of `{instanceId, typeId, hiredDay, lastUpkeepDay}`, default `[]`) is `goblinwar_party`'s sibling key — written from index.html's Guard House "Hire a Mercenary" action (see [locations-and-camp.md](locations-and-camp.md) and [player-state.md](player-state.md)), read here. `MAX_PARTY_SIZE` (`3`) is a shared cap across both keys combined, shown as a live "n / 3" counter. Mercenaries are deliberately anonymous, per the project owner — no name, just a role from a small fixed `MERCENARY_TYPES` catalog (duplicated from index.html per the no-modules convention: Hired Sellsword, Mercenary Archer, Veteran Guard). Each role does have its own real portrait now, under `assets/mercenaries/` (same transparent-background, 600px-longest-edge convention as `assets/party/`) — but deliberately faceless (full helm or a shadowed hood, never a face), so the art stays consistent with "hired sword, not a character" even though it's no longer the placeholder hero-silhouette SVG a portrait-less companion would use. Each mercenary row shows that portrait with the role's `title` where a companion would show its own `name`. Each mercenary row also gets a **Dismiss** button (`dismissMercenary`, `confirm()`-gated same as quests.html's Abandon), since letting a hired sword go is always available — unlike a companion, which can't even be recruited yet, let alone dismissed. This is also party.html's first real mutation, so it grew its own `#toast`/`showToast()` (same pattern as character.html/inventory.html/quests.html) to confirm a dismissal. `render()` now draws companion rows and mercenary rows together into one combined list, falling back to the original static "No followers yet" block (`#empty-state`) only once both are empty.

Both `goblinwar_party` and `goblinwar_mercenaries` are part of the character snapshot shape (see [characters.md](characters.md)) so a recruited companion or a hired mercenary survives a save. No combat participation yet for either — a mercenary fills a party slot and costs daily upkeep, but doesn't yet fight alongside the player in `combat`; that's flagged as separate future work in [roadmap.md](roadmap.md).

## achievements.html — Achievements

Not one of the five toolbar tabs — reached from a Settings menu item instead (`location.href='achievements.html'`, right above the existing Change Log one), the same pattern changelog.html already uses to keep the toolbar from getting crowded. Five categories, each a `.section-label` heading over a list of cards, every card showing a name, a one-line description, a progress bar, and an `X / Y` count — a card's earned/locked state (checkmark vs. lock badge, gold vs. green styling) is derived purely from `current >= target`, never stored separately, since every progress source it reads only ever grows:

- **Exploration** — "Grand Tour": every Capital settlement visited. Cross-references the new `goblinwar_visitedBurgs` array (index.html's `recordVisitedBurg(burgId)`, called from `showLocationView`) against `assets/travel-graph.json`'s own `tier === 'capital'` burgs, fetched on load the same way character.html fetches it just for a name lookup — 24 Capitals in the current world data.
- **Bestiary** — "Monster Hunter": every `ENEMY_VARIANTS` name defeated at least once. Reads the new `goblinwar_defeatedVariants` object (`{enemyName: true}`, written by index.html's `recordDefeatedVariant(name)` for every enemy in `endCombat('victory')`'s `enemies` array) against a local `ALL_ENEMY_VARIANTS` list — duplicated from index.html's `ENEMY_VARIANTS` per the no-modules convention, so a new variant added there needs a matching entry added here too or "Monster Hunter" can never complete.
- **Combat** — three cumulative kill-count milestones (Blooded/Battle-Hardened/Legend of the Realm at 10/50/150), summing every race's count in the existing `goblinwar_kills` object — no new tracking needed, since kills were already cumulative (this is the same data character.html's Titles line reads, see [player-state.md](player-state.md)).
- **Quests** — three milestones (Errand Runner/Reliable Hand/Hero for Hire at 5/15/40) off the new `goblinwar_questsCompletedTotal` counter. This couldn't reuse `goblinwar_completedQuests` directly, since that array trims to `COMPLETED_QUESTS_MAX` (20) — the counter is a separate, never-trimmed increment added right alongside it in `recordCompletedQuest` (index.html), so both of that function's call sites (delivery turn-ins and kill-quest payouts, see [quests.md](quests.md)) cover it automatically.
- **Progression** — three level milestones (Rising Star/Seasoned Adventurer/Master of the Realm at 5/10/20) off the existing `goblinwar_level` — no new tracking.

All three new keys (`goblinwar_visitedBurgs`, `goblinwar_defeatedVariants`, `goblinwar_questsCompletedTotal`) are part of the character snapshot shape (see [characters.md](characters.md)) so achievement progress survives a save/switch rather than resetting.

## Adding a new secondary page

Follow the existing pattern rather than inventing a new one: copy the shared CSS block (`:root` custom properties, `header`/`#back-btn`/`main`/`.subtitle` rules are near-identical across all five files), add the nav icon + `onclick="goTo('yourpage.html')"` to index.html's `#nav-icons` (see the cache-busting convention in [../CLAUDE.md](../CLAUDE.md) for why it's `goTo()` and not a bare `location.href`), and read `localStorage` directly rather than trying to pass state through the URL or a shared script — see root [CLAUDE.md](../CLAUDE.md) on why there's no shared module. Don't forget the two gate scripts in `<head>`/near the bottom of `<body>` (see [accounts.md](accounts.md)) — every player page needs them.
